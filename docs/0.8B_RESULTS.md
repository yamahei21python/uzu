# 0.8B の結果まとめ（2026-11-08）

対象: Qwen3.5-0.8B（`Qwen/Qwen3.5-0.8B`）。RHT block 32 + INT4 group 32 + YAQA。
別段の注記がない限り **dedup コーパス / 100 chunks / max_tokens 128**。

## 0. 指標

- **BPC の相対差**（同じ言語内）: `Δ% = (bpc_candidate / bpc_bf16 − 1) × 100`
- PPL の比ではない。PPL の絶対値・比は言語間で比較しない
- BF16 baseline: EN 35.376〜35.386 / JA 43.421〜43.430（レーン間で 0.02〜0.06% の差）

## 1. 変換だけ（校正なし）

| 条件 | EN | JA | chunks |
|---|---:|---:|---:|
| RTN（mixed コーパス扱いなし） | 3.01% | 4.01% | 100 |
| RTN（旧・50 chunks） | 2.81% | 4.15% | 50 |

## 2. 校正コーパス（s32 / q128 / d1e-3 / uniform4）

| コーパス | EN | JA |
|---|---:|---:|
| enonly | 3.02% | **9.67%** |
| mix35 | 3.36% | 3.43% |
| mixed50 | 3.36% | 3.70% |
| mix65 | 3.81% | 3.52% |
| jaonly | 7.13% | 3.71% |

- enonly は JA が壊滅（校正分布のミスマッチ）
- mixed50 / mix35 が実用域。混合比 50 vs 65 の差は seed 幅内で**有意でない**

## 3. damping（s32 / q128 / uniform4）

| damping | mixed50 EN | mixed50 JA | enonly EN | enonly JA |
|---:|---:|---:|---:|---:|
| 1e-3 | 3.36% | 3.70% | 3.02% | 9.67% |
| 1e-2 | 2.16% | 2.73% | 1.91% | 6.52% |
| 1e-1 | 1.99% | 2.26% | 2.26% | 4.20% |
| **1e0** | **1.58%** | **2.04%** | **1.70%** | **3.15%** |

- s32 では **1e0 が最良**まで改善
- s64 / q512 では 1e0 は悪化（1.95 / 2.22）。**samples が多いほど最適 damping は小さくなる**
- 解釈: damping は「ヘッセ推定のノイズ補正」。samples と同じ方向のレバー

## 4. samples × max_tokens（damping 1e-2 / uniform4）

| 条件 | 総トークン | EN | JA | デバイス |
|---|---:|---:|---:|---|
| s16 q128 | 2k | 2.80% | 3.82% | CPU |
| s16 q256 | 4k | 3.01% | 4.33% | CPU |
| s16 q512 | 8k | 1.97% | 2.52% | GPU |
| s32 q128 | 4k | 2.16% | 2.73% | CPU |
| s32 q256 | 8k | 1.60% | 2.76% | CPU |
| s32 q512 | 16k | 1.99% | 2.26% | GPU |
| s64 q128 | 8k | 2.44% | 2.93% | CPU |
| s64 q256 | 16k | 1.86% | 2.42% | CPU/GPU |
| s64 q512 | 32k | 1.59% | 1.98% | GPU |
| s128 q512 | 65k | 1.42% | 1.53% | GPU |

- samples が効く（s16→s64 で改善）。seq も効くが、samples の方が支配的
- 32k → 65k の改善は seed 幅内で**有意でない**。校正時間は 2 倍
- q1024 は calibration が失敗（code 1、原因未特定）

## 5. 8bit 配分（s32 / q128 / d1e-1）

| 配分 | EN | JA | サイズ増 |
|---|---:|---:|---:|
| uniform4 | 1.99% | 2.26% | — |
| down + out_proj | 1.39% | 1.70% | +0.06GB |
| **down + out + qkvg + out_projection（wide8）** | **1.13%** | **1.24%** | +0.08GB |

- down/out の寄与は両言語で seed 幅超え
- wide8 の追加分は **JA で有意**、EN は wide8 seeds 待ち

## 6. 校正 dtype・デバイス

| 条件 | EN | JA |
|---|---:|---:|
| CPU / f32（基準） | 2.16% | 2.73% |
| **CPU / bf16** | 3.21% | 3.84%※ |
| GPU TP=2 / f32 | 2.51% | 3.04% |
| CPU / bf16（q512 s16） | 1.34% | 2.54% |
| GPU / f32（q512 s16） | 1.97% | 2.52% |

※ bf16 は d1e-3 の条件（他は d1e-2）。同条件比較は `calib-device-cpu-bf16` で実施中。

- **GPU(TP=2) の校正は CPU より 0.3pp 悪い**（JA で seed 幅超え）
- 校正は CPU で行い、GPU の校正値と混ぜない。eval はデバイス差 0.02% で混在可
- bf16 校正は CPU の q512 を可能にした（f32 は SIGKILL）

## 7. ばらつき（seed 幅）

| 設定 | EN | JA |
|---|---:|---:|
| s32 q128 d1e-3（mixed50） | 0.89pp | 0.23pp |
| **s32 q128 d1e-1（mixed50）** | **0.44pp** | **0.25pp** |
| s64 q256 d1e-2（GPU 3 seed） | 0.30pp | 0.53pp |

- **この幅以下の差は主張しない**
- 同じ条件を別レーンで回すと完全一致する（s32 q128 d1e-2: 2.16 / 2.73 が 3 回再現）

## 8. 現時点の最良

| 用途 | 設定 | EN | JA |
|---|---|---:|---:|
| **実用最良（CPU）** | wide8 + d1e-1 / s32 q128 / mixed50 | **1.13%** | **1.24%** |
| 参考（CPU） | down-out8 + d1e-1 | 1.39% | 1.70% |
| 参考（GPU） | s128 q512 d1e-2 | 1.42% | 1.53% |
| 参考（校正だけ揃えた素） | RTN | 3.01% | 4.01% |

**CPU 20 分/条件で 1.1〜1.2% まで到達**。GPU は 0.8B では不要。

## 9. 未実施・失敗

| 項目 | 状態 |
|---|---|
| `s32_q1024` | calibration が code 1 で失敗（seq 上限は未検証） |
| wide8 の seed 3 本 | Muse 実行中（EN の確定用） |
| embedding bits 4 vs 8 | Muse 実行中 |

| group 16 vs 32 | 未検証（g64 以上は 0.8B で不可） |

## 10. 結論

1. 校正は **mixed50（または mix35）+ samples 多め + damping 適正**が効く
2. **8bit を出力側に寄せる**のが最も安い改善（+0.08GB で 1.85→1.13%）
3. samples と damping は代替関係。samples を増やすなら damping は下げる
4. 0.8B は CPU で完結する。GPU は q512 など CPU で不可能な条件のみ
5. 3% 前後の差を議論するときは seed 3 本（EN 0.4〜0.9pp / JA 0.25〜0.53pp）が必須

## 11. TPS: 公式モデルとの比較（2026-11-08 実測）

MacBook Air M3 16GB、`cli bench`（UI 無し、tokens 512 × 2 runs、back-to-back 測定）。

| モデル | サイズ（実行時） | Generate |
|---|---:|---:|
| 公式 `alibaba:qwen3.5:0.8b:mirai:mirai-m:4` | 0.521GB | **142.9 t/s** |
| **我々の変換（RTN + embedding 4bit）** | **0.521GB** | **143.0 t/s** |
| 我々の変換（RTN、embedding は BF16 のまま） | 0.92GB | 87.9 t/s |

- **embedding を量子化するだけで公式と同等**になる（サイズ・速度とも一致）
- 校正（YAQA）・damping・8bit 配分は**速度にほぼ影響しない**（バイト数が同じため）
- 測定は熱の影響で ±5% 動く。公式→我々→公式の順で回すと 132 / 143 / 143 と収束した

**速度の要件は2つだけ**: lalamo/uzu 形式への変換、embedding/readout の量子化。
品質の要件（YAQA / damping / 8bit）は速度と独立。
