# R0 実施チェックリスト（uzu 実機・測定フェーズ）

- 対応文書: FINAL_PLAN.md（再現フェーズ R0、判断ゲート G0）／ FINAL_REPORT.md v3.1
- 目的: 学習も梱包もせず、既存の束だけで「投資判断に要る数値」を先に取る
- 測定条件は全行で固定する: 測定プロンプト集合（measure_prompts.jsonl）、生成条件（thinking の有無、温度、最大生成長）、チップ、uzu の版。条件が違う行は比較に使わない
- **このマシンは MacBook Air M3（ファンレス、メモリ 16GB）**: 持続負荷でサーマルスロットリングが起き、後ろの測定ほど遅くなる。1回の測定は短く保ち、測定の間隔と順序を記録する。熱い状態で取った行は比較に使わない
- **Modal の併用（小さいものは M3）**: 測定は L（8bit）でなく M（4bit）から始める。Modal には利用上限があるので温存し、小さい処理（短時間で終わる生成・変換・小規模測定）はこの M3 で動かす。Modal は、実機で回らない規模のものと、GPU が要る SGLang 先行測定・本格学習だけに使う。uzu の測定そのものはこの Mac でしか測れない（チップ依存）（計画書の役割分担「計算資源の使い分け」）
